# Contextual spoken reply openings

Mode: Improve. Scope: replace robotic, unrelated filler chains with a coherent start to the actual answer. Contract: preserve Edge Ava/default settings and the chat/orb layout, wait for the user transcript and model's interpretation, speak at most one model-selected optional recorded opening as part of the same visible/stored answer, then continue without another acknowledgement or random stall loop. Keep unknown/direct answers intact; preserve interruption, captions and native sample-clock ordering. Contextual fit takes priority over making noise immediately. No claim that variable provider latency disappears or that timing alone proves naturalness.

Environment: physical M2 Mac, macOS 27.0.1, optimized Swift/Node native voice path. Source and old independent filler bank archived under build/context-openings-20261022/before. New recorded assets use the same existing Edge voice, rate and pitch. No saved user conversations were used for evaluation.

## Why the old approach failed

The native player selected a random clip before transcription, then alternated cached words/phrases to occupy time. Neither the meaning of the user message nor the planned answer controlled those choices. Sample-contiguous audio therefore sounded like unrelated hesitation fragments. That independent filler subsystem is removed from production Native code rather than expanded again.

## New behavior

The reply model sees an optional catalog of complete, coherently recorded openings, with intent descriptions. It selects one only when the user's actual meaning, tone and character fit it, and can skip all of them. Its continuation must carry on from that sentence, not restart with a greeting or another acknowledgement. Recent actual reply openings are included to discourage repetition without selecting an inappropriate alternative merely for variety.

The opening is ordinary model response text: it appears once in speech, captions, stored reply and model context. There is no separate preface sound or pre-transcript acknowledgement. Exact matching uses the recorded audio immediately; new continuation speech is synthesized in parallel. The opening is preserved as a single TTS chunk even if it has two sentences, while the continuation uses natural sentence boundaries instead of the old first-25-character cut. Unknown starts pass through normally, so an uncached direct answer remains the model's own answer. An exact immediately echoed opening is removed consistently from both text and speech; arbitrary content is not deleted.

Ava recordings are complete utterances, with no artificial stutter or stitched hesitation sounds. The cache is available only for the exact Edge Ava/rate/pitch configuration and verified assets; other voices/providers use the existing speech path. Missing/corrupt assets fail back to normal generation. Audio stays on the existing native answer queue. External codec silence is trimmed with 20 ms lead/60 ms tail margins; word/mouth timestamps and duration are adjusted to the same retained waveform.

## Validation plan and limits

- Stream fragmentation, case/apostrophe/terminal-colon matching, unknown/partial passthrough, duplicate suppression in both text and speech, exact voice/rate/pitch eligibility, and cache asset validation.
- Full native voice endpoint and local transport with an actual cached Ava opening plus a coherent prerecorded Ava continuation delayed 2.2 seconds, muted output only. Check text/spoken agreement, two speech chunks, aligned captions, no filler marks and sample-clock ordering.
- Live configured Groq GPT-OSS 20B on ten synthetic meaning cases: greeting, criticism, loneliness, success, personal opinion, explanation, ambiguity, quoted emotion, a direct numeric answer and gratitude. Preserve raw results and failures; body speech is stubbed in this semantic test. This checks actual model choices, not a hand-written input keyword classifier.
- Existing conversation, phrase/cancellation, provider/STT, worker and native lifecycle checks, then signed bundle installation with unchanged UI hashes.

The tradeoff is explicit: first meaningful speech waits for STT and the model to choose its opening; it is no longer an unrelated noise at 350 ms. If the model declines the catalog, or Edge takes longer than the opening to produce the continuation, a thinking pause can remain. The system will not resume robotic filler chains to conceal that. This is a naturalness change, not a guarantee of instantaneous or universally gap-free live speech.

## Results and iteration

The initial live-model evaluation produced nine results before a provider failure on gratitude. Gratitude passed independently. A later ten-request attempt also stopped at the last request with `Groq connection failed`; the raw failed attempt is retained. The meaning review therefore combines ten distinct synthetic cases across runs, not a single failure-free ten-request batch. Six selected a matching recorded full opening; four answered in their own wording. All ten selected openings were relevant to their expected intent, or the model skipped the catalog; no independent filler events were emitted. This is a small hand-reviewed set, not a measured universal relevance percentage.

Review caught an actual mismatch: the generic external-problem acknowledgement steered criticism of a previous off-topic answer toward a generic technical explanation. Merely tightening the prompt was insufficient. The criticism recording and its intent description were revised to acknowledge the missed point directly, and the external-problem option now explicitly excludes conversational feedback. In the retest, the model chose its own shorter wording: “You're right, I missed your point.” and answered the original question. That uncached wording was preserved rather than forcing the longer recording. Unknown/uncached starts now also use full sentence boundaries so the old early comma/25-character cut does not fragment this path. The tagged reply mode keeps its existing sentence directives; they are parsed before opening recognition and never reach TTS. Whitespace around directives is normalized for cache matching while the spoken words remain unchanged. Fragmented tagged and plain replies are both tested.

Regression tests passed for fragmented streams, leading whitespace, apostrophe/terminal-colon variants, partial/unknown text preservation, exact voice/rate/pitch matching, asset checks and exact echo removal from text and speech. The full native voice fixture passed: a coherent cached opening and delayed prerecorded Ava continuation produced two actual answer chunks, matching displayed text, aligned word timings and no independent filler stamps. Signed sample-clock handoff estimates were -29/-52 ms in early runs and -22 ms in the final run; this definition subtracts a delayed dataPlayedBack callback and can be negative, so these are not acoustic overlap claims. Both buffers were queued on the same player. A constructed listening preview is saved as context-demo.wav.

The optimized staged app built and passed the existing protocol, context/conversation, phrase/backpressure/cancellation, STT/provider, Edge worker, voice/UI bridge and native lifecycle/input checks. Actual meaning outputs, failed attempts, source hashes and native results are under build/context-openings-20261022. No saved conversations or voice preferences were modified.
