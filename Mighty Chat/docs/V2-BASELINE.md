## Measurement contract and environment

- Physical Mac14,2, Apple M2, 8 GiB RAM; macOS 27.0.1 (26A434); AC power, battery 100%; no thermal or performance warning reported. Swift 6.4, optimized native runner (`-O`), bundled app Node runtime, existing default audio route. Full Xcode is not installed (Command Line Tools selected).
- Actual Groq `whisper-large-v3-turbo` STT and streaming `openai/gpt-oss-20b` replies; actual Edge `en-US-AvaMultilingualNeural` synthesis; real MP3 download/decode, AVAudioEngine output and `.dataPlayedBack` acknowledgements. Keys are read silently by the existing signed credential broker, passed only to the backend environment, and never included in artifacts.
- Five fixed spoken inputs are generated by live Edge before each timed run and cycled within that session. Because the refined run was resumed in a new session, the 20 completed inputs have counts 5/5/4/3/3 rather than a balanced four repetitions each. They exercise greetings, preferences and short personal reactions; their text is in the runner source. Recorded input goes through the real hold endpoint and STT. This is a **controlled voice-input** baseline, not a human microphone or physical Fn-key test. Audio capture is started normally, but the runner disconnects microphone ingestion before injecting the recorded input.
- Start is the native hold release timestamp, before endpoint PCM finalization/upload. Stop is confirmed positive native played-sample progress for playback start, and final drained playback after played-back acknowledgements for audio complete. This is not an acoustic loopback measurement or an exact first-word detector; provider leading silence and device latency are not separately measured.
- Each of the two refined sessions starts with a fresh backend/call session; input generation happens outside timed turns; live Edge worker cold for the first reply, reused thereafter. Conversation history grows with the existing last-16-row native limit. Provider caches are neither assumed nor controlled. The host's existing internet connection was used, without artificial delays; bandwidth and remote load were not measured.
- Final series ran after heavy compilation and verification, without overlapping test audio or builds. Ordinary host apps stayed open. No 3D model was loaded in the measurement runner: these numbers cover the provider/native path and do not establish performance with Babylon rendering under load.
- An initial 20/20 pilot is retained separately. It used the earlier commit/scheduled-playing observation boundaries and overlapped verification; it is **not pooled** with the final series and is not a before/after performance comparison. The final series was rerun after tightening instrumentation, not selected for faster results.

`face_first_expression` is wired to a successfully applied, mapped non-vowel/non-blink morph above 0.01 in the existing mixer. A received message, attempted missing morph, vowel, blink or residual listening expression cannot create the mark. Renderer checks cover real adapter/mixer writes and clock export.

The current production call deliberately supplies `neutral` intensity 0; it has no listening/thinking face driver. Accordingly, no listening response or non-neutral call expression is fabricated. These two baseline deltas are unavailable (0/20), and the native baseline runner also has no model. ## Baseline-based budgets (section 9 adjustment)

The former 400 ms Edge-ready and 1.5 s first-audio proposals are not supported by this series. For this setup, use the following initial regression budgets: round 1.25 × each measured percentile upward to the next 0.1 second. These are engineering gates with explicit 25% headroom, **not new measurements or promised improvements**. WP7 can later tighten them with matched data.

| Stage | Initial p50 budget | Initial p90 budget |
|---|---:|---:|
| LLM request → first text token | 0.7 s | 1.0 s |
| First phrase → Edge audio ready | 4.0 s | 5.8 s |
| Hold release → confirmed native playback | 5.5 s | 7.4 s |

Keep the existing ≤100 ms sentence-to-phrase gate (measured positive overhead stays below it). The ≤150 ms thinking-pose target is unmeasured and remains a later Director requirement. Budgets apply to this controlled provider/native setup only. No latency optimization or quality improvement is claimed by WP0.

## Clocks, ring and export

All new collection, HTTP endpoints, native relay fields, observers and overlay activation are behind `MIGHTY_DEBUG_PERF=1`; default is off. No other v2 flag is enabled. Node `performance.now()`, native `systemUptime` and renderer `performance.now()` are never directly subtracted without translation.

Native and renderer clients take five four-timestamp HTTP clock probes and retain the smallest round-trip uncertainty. Offset = `((serverReceive-clientSend)+(serverSend-clientReceive))/2`; uncertainty = `(roundTrip-serverProcessing)/2`. Imported client stamps are translated into the backend monotonic domain. Exported clock offsets and uncertainty accompany each row for audit. No wall clock is used for latency. Backend origins differ between the two run processes; only within-turn deltas are pooled, never absolute timestamps across processes. Native hold release replaces server input-receipt time; the latter remains `input_commit_received`.

The backend keeps at most 128 turn rows; native keeps at most 128 tickets. First occurrence wins per mark. Export is one JSON line per turn, containing IDs, timestamp maps, clock offsets and clock uncertainty only. No prompts, transcript/reply text, URLs, tokens, keys or audio are included. Reads are snapshots, not append-only duplicated rows.

Authenticated local routes (same `X-Mighty-Token`, loopback binding and existing protections):

- `POST /api/debug/perf/clock`: four-timestamp probe response.
- `POST /api/debug/perf/sample`: bounded, validated native/renderer stamps; rejects invalid sources, fields, identities and timestamps.
- `GET /api/debug/perf/export`: current bounded JSONL snapshot (`application/x-ndjson`, no-store).

All routes return 404 when the flag is off and 401 without authentication. Existing version-2 call envelopes and version-1 renderer speech contracts are unchanged; debug fields are additive. Missing/rejected debug transport never blocks audio or rendering. Native `exportPerformance()` waits for its queued sample uploads before fetching a correlated snapshot.

## Reproduce and audit

From the workspace, run `bash "Mighty Chat/scripts/measure-v2-baseline.sh"`. It builds an isolated signed runner, uses the installed signed broker/runtime, and writes under `Mighty Chat/build/wp0-baseline`. It does not replace the installed app, change saved credentials, or use any mock providers. Each real turn is bounded by a 60-second timeout. Failures stop a run and are recorded; successful turn exports are saved after each turn. Set `MIGHTY_BASELINE_TURNS` to a bounded smaller count when completing a stopped series, keeping every prior outcome and source hash. The final baseline combines 12 completions from the stopped run and 8 from its continuation; all 21 attempts are accounted for.

Recompute results with `node "Mighty Chat/scripts/report-v2-baseline.cjs" <turns.jsonl>`. The checked-in [raw final turns](baselines/wp0-2026-10-19/turns.jsonl), [final statistics](baselines/wp0-2026-10-19/report.json), [run outcome](baselines/wp0-2026-10-19/run.json), [environment/source hashes](baselines/wp0-2026-10-19/environment.json), the two separately named refined-part exports/outcomes, and separately named pilot files contain no content or credentials. ## WP1 — provider prefix-caching verification (19 October 2026)

No cache hits, cache discounts or latency improvement were measured for WP1. Static identity/style/mode remain byte-identical between unchanged turns; dynamic memory follows. Compact bounds are enforced regardless of caching, and short prompts are not padded to chase cache eligibility.

- **Groq:** official documentation lists automatic caching for GPT-OSS 20B/120B and the safeguard model, with model-dependent minimums; hits are not guaranteed. The owner's GPT-OSS 20B is eligible in principle. [Groq prompt caching](https://console.groq.com/docs/prompt-caching).
- **OpenAI:** caching operates on eligible prompt prefixes; minimums and settings depend on model/request generation. The existing GPT-4.1-mini Chat Completions adapter is retained, and no newer-model cache feature is assumed or enabled. No hit-rate claim is made. [Official OpenAI prompt-caching documentation](https://developers.openai.com/api/docs/guides/prompt-caching).
- **Anthropic:** documented cache breakpoints/automatic controls and model-specific minimum lengths must be satisfied. The current adapter sends a system string without `cache_control`, so WP1 does not claim explicit Claude caching. [Claude prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching).
- **Gemini:** official docs describe default implicit caching for Gemini 2.5+, subject to model minimums and actual hits. The app uses the OpenAI-compatible endpoint; cache benefit for this exact path was not established by a live check. [Gemini context caching](https://ai.google.dev/gemini-api/docs/caching).

WP1 functional, packaging, token-budget and recall evidence is in [WP1-MEMORY.md](WP1-MEMORY.md); it is not an addition to the WP0 latency sample.

## WP7 comparison — 20 October 2026

**Final configuration: 21 attempted, 20 completed, one unclassified provider/playback error.** Retain all six completed turns from the first session and resume the same five-input cycle at offset six for 14 completions in a second session. Every input has four completed observations. The failed attempt has no exported timing snapshot; it is counted as a failure and assigned no invented duration. Session restart resets that call's history. The WP0 baseline likewise has 20 completions from 21 attempts. No successful observation from the final configuration was discarded.

Groq `openai/gpt-oss-20b` + Edge `en-US-AvaMultilingualNeural`, real transcription/reply/synthesis and native decoded sample-clock playback. `MIGHTY_STREAM_CHAT=1`, debug timing enabled; memory, face, energy and gesture flags disabled. The four measurable section 9 gates pass: first token ≤700/1,000 ms p50/p90, sentence-to-phrase ≤100 ms, phrase-to-TTS-ready ≤4,000/5,800 ms, and commit-to-native-playback ≤5,500/7,400 ms. `scripts/check-latency-report.cjs` verifies counts, completeness and these unchanged budgets. The new first-token p90 and text-completion p90 are higher than WP0, despite earlier playback; the full table is retained rather than claiming every stage improved.

**Chunk gaps remain:** 34 native transitions; signed estimate p50 **140.13 ms**, p90 **1971.95 ms**, range -28.01 to 2833.02 ms. These use next sample-clock start minus previous `.dataPlayedBack` callback. Slightly negative estimates reflect callback latency, not overlapping sound. Large positive gaps are observable pauses, compatible with a short first phrase finishing before Edge's next synthesis is ready. Scheduler overlap/backpressure checks and all completed turns show progress, not gap-free speech. WP0 has no per-chunk marks, so no before/after gap improvement is asserted.

Maximum native/backend clock uncertainty is **0.553 ms**, plus the existing 40 ms playback observation cadence and callback scheduling. There is no renderer loaded: listening/thinking/expression onset is unavailable in this series, not zero. Prior WP4 evidence remains separate. This is a positive native playback proxy, not acoustic first-word latency or physical key-to-pixel timing.
