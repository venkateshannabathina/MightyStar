## 2026-10-19 — WP0 source verification and resolutions

1. **Local input begin differs from backend upload begin.** `LiveCallRuntime.commit` sends backend `input.begin` after capture ends, before PCM upload. It is not hold start. WP0 records local `input_begin` as a supplementary native timestamp and records `input_commit` at native hold release (automatic endpoint finalization uses the captured speech-end time). Server receipt remains `input_commit_received`. No listening response is inferred from upload activity.

2. **Synthesis completion is not audio completion.** `ConversationSession` sends `speech.audio.complete` when the synthesis queue drains, potentially before ready chunks finish playing. `audio_complete` is observed only when native playback is fully drained after `.dataPlayedBack` callbacks. Existing scheduling and acknowledgements are unchanged.

3. **Legacy “playing” can precede sample progress.** `PlaybackEngine` substitutes zero for a missing player clock in the existing renderer snapshot. The WP0 timing observer now requires a non-nil, positive actual played-sample count before recording `playback_start`; it does not change the existing snapshot behavior. This is a playback observation on the existing 40 ms cadence, not acoustic proof of first-word onset. The final series was rerun after this refinement; the earlier pilot is separate.

4. **No listening/thinking face driver exists; calls intentionally request neutral.** There is no legitimate `face_listen_onset` or thinking-pose time to measure. Current call performances set neutral intensity 0, so no non-neutral expression should be fabricated. The mapped, applied-expression observer is wired at actual legacy mixer output; it excludes vowels, blinks, absent morphs and residual expressions during listening. The baseline runner also does not load a model. Face deltas are explicitly unavailable (not zero); implementation of those missing behaviors stays in WP3/WP4. No listening phase or new expression engine was added in WP0.

5. **First phrase can precede first sentence.** Existing `PhraseChunker` has timed/length flushes before a complete sentence. Signed sentence-to-first-phrase deltas can therefore be negative. WP0 preserves them and uses the existing sentence rules, including a final-only boundary when streaming ends. It does not change chunking policy (WP7).

6. **Clocks have different origins.** Node, native and renderer timestamps cannot be subtracted directly. WP0 now uses five four-timestamp probes per client, translates into backend monotonic time, exports the chosen offset/uncertainty, and retains one bounded row per full turn identity. The previous unresolved cross-clock export limitation is resolved.

7. **Edge exposed completed audio only.** Resolved within WP0: the helper optionally reports its first nonempty provider audio bytes; the persistent worker emits a content-free event immediately, and the backend observes its arrival. `tts_first_byte` includes the worker-to-Node IPC observation delay and is distinct from file-ready time. OpenAI's optional observer reads its first nonempty response-body bytes. Both retain the existing flag-off paths and cancellation checks.

8. **The former latency proposals were unmeasured.** The final 20-turn controlled Groq + Edge provider/native baseline replaces unsupported 400 ms Edge-ready and 1.5 s first-audio proposals with baseline-derived, explicitly provisional regression budgets in section 9 of the local spec copy and V2-BASELINE.md. These are not universal targets or measured improvements. No latency optimization has been implemented.

9. **Work package heading order conflicts.** The document places WP7 before WP6. The user's instruction to work in numerical order takes precedence. No later work package has been started.
