## Changes

- Calls can emit the first clause at a comma/dash or a word boundary near 25 characters. Sentence parsing/probes and later phrases retain existing rules. Complete earlier sentences always win. No text is duplicated or dropped when deltas split punctuation.
- The existing scheduler still prepares the next phrase while playing, with two ready chunks and bounded queue/backpressure. It is unchanged. Native playback exports `chunk_0_start/end` through `chunk_63_start/end` in the authenticated, bounded timing ring. Starts use the decoded sample clock; ends use `.dataPlayedBack`. Gap estimates are signed and can be slightly negative because callback delivery trails sample playback. They are not acoustic measurements; the native observation cadence is 40 ms. Positive gaps are reported, never replaced with zero or hidden.
- Reply budgets default to 220 call / 300 chat, clamped 64–1,200 per character using `callMaxTokens` / `chatMaxTokens`. **Groq GPT-OSS retains the existing 900 default**, because real 220-token trials produced an empty reply. Its reasoning and visible answer share the cap. Stream-enabled Groq GPT-OSS requests select documented `reasoning_effort: low`; other providers and flag-off requests do not receive that field. There is no inference about answer quality. Supported levels are listed in the [Groq API reference](https://console.groq.com/docs/api-reference).
- The native character editor exposes call/chat limits and an ordered fallback list only with the stream flag. Profiles accept `aiFallbackProviders` as provider IDs or `{aiProvider, aiModel}` objects; existing model overrides survive edits. Only the existing Groq/OpenAI/Gemini/Anthropic endpoints are supported. Keys still come from the existing protected environment/Keychain path. Unconfigured/duplicate-primary entries are skipped; the first configured alternative is tried once. There is no automatic cross-provider default for an empty list.
- Connect errors, HTTP 5xx or a three-second first-token deadline may trigger that single retry. Abort the failed attempt and commit the provider on its first upstream text token, including a directive fragment. After commitment, errors fail the reply; never append a second provider. Authentication/rate-limit/malformed-stream/empty-reply errors do not silently switch providers. Selected fallback model metadata is accurate.
- Built-in Node `fetch` already pools HTTP connections. A real local server test verifies five sequential SSE requests use one TCP connection; no extra agent dependency is introduced. Error response bodies and stream readers are cancelled.
- With memory and streaming enabled, local worker embedding starts before synchronous prompt setup. Retrieval has a 20 ms deadline measured from that start. A timeout sends the already-built prompt without semantic retrieval, emits a content-free debug timeout receipt, and sets a correlated call timing mark. Late results are discarded and epoch/close-fenced. Core facts and the existing summary remain in the base prompt. JavaScript timers cannot preempt synchronous SQLite/context work; elapsed time is checked before accepting a result.
- Existing fact extraction, mood and summary jobs remain fire-and-forget after response completion; new integration checks verify ordering. Completed-turn persistence stays synchronous for idempotency.
